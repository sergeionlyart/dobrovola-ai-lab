# Dobrovola AI Native Lab: базовая методика

## 1. Что мы преподаём

Мы не продаём отдельный навык «писать промпты». Мы учим человека проходить полный цикл создания цифрового продукта вместе с AI-агентами:

```text
Замысел → Контракт → Контекст → План
→ Исполнение → Доказательство → Релиз
```

Продуктом обучения являются одновременно:

- работающий цифровой артефакт;
- документация проекта;
- история решений и задач;
- способность участника самостоятельно повторить процесс.

## 2. Семь этапов

### Замысел

Участник определяет пользователя, проблему, ценность и одно основное действие.

### Контракт

Идея превращается в blueprint, границы первой версии и проверяемые критерии приёмки.

### Контекст

Проект получает короткий `AGENTS.md`, необходимые роли, skills и ссылки на канонические документы.

### План

Работа разбивается на milestones и небольшое число ограниченных задач в Linear.

### Исполнение

Руководитель формирует контракт задачи. Исполнитель реализует одну задачу без самовольного расширения scope.

### Доказательство

Результат подтверждается diff, commit или PR, тестами, скриншотом, URL и отчётом исполнителя.

### Релиз

Аудитор независимо проверяет продукт. Критические дефекты устраняются, после чего версия публикуется.

## 3. Три роли

### Lead — руководитель

Читает документы, планирует, формирует задачи и принимает результат. По умолчанию не пишет продуктовый код.

### Builder — исполнитель

Реализует одну ограниченную задачу, запускает проверки и возвращает доказательства.

### Reviewer — аудитор

Работает независимо и преимущественно read-only. Сравнивает результат с критериями, ищет дефекты и не подменяет исполнителя.

## 4. Linear и GitHub

Linear — операционный журнал проекта: цель, текущее состояние, блокеры, решения и критерии приёмки.

GitHub — источник артефактов и доказательств: код, документы, история изменений, проверки и релизы.

Ни один из инструментов не заменяет человеческое решение о качестве результата.

## 5. Правила учебного модуля

- Сначала минимально законченный продукт, затем усложнение слоями.
- Один модуль — один основной пользовательский сценарий.
- Каждое занятие заканчивается артефактом и контрольной точкой.
- Красивый результат без работающего сценария не считается готовым.
- Код, созданный агентом, должен быть понятен и проверен человеком.
- Инфраструктурная сложность не должна заслонять основной учебный навык.
